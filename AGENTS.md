# Antigravity Workspace Guidelines: Token & Context Optimization

Для обеспечения максимальной скорости ответа и минимизации Context Bloat соблюдаются следующие обязательные правила:

## 1. Защита от Context Bloat при работе с терминалом и логами
- Большие выводы команд (сборка, тесты, линтер) **обязательно** фильтровать на месте через shell-конвейеры:
  - PowerShell: `| Select-Object -Last 20`, `| Select-String -Pattern "error"`
  - Bash: `| tail -n 25`, `| grep -E "error|warn"`, `| jq`
- При объемных логах (tsc, vitest, eslint, большие JSON) делегировать чтение сабагенту `log-analyzer` (Gemini 3.8 Flash, effort: low). В глобальный контекст сессии сырые логи не передавать.

## 2. Баланс вызовов (Zero-Overhead Rule)
- Разовые мелкие операции (поиск 1 конкретной строки, чтение одного небольшого файла, быстрая проверка наличия файла) выполнять напрямую в основном чате.
- Не запускать сабагентов для тривиальных действий, чтобы избежать накладных расходов на инициализацию подсессии.

## 3. Параллельный вызов инструментов (Parallel Tool Calls)
- Для независимых операций (одновременное чтение нескольких файлов, параллельный grep по разным маскам, одновременный запуск проверок) обязательно генерировать вызовы инструментов параллельно в рамках одного сообщения. Gemini 3.8 Flash оптимизирован под мульти-вызовы.

## 4. Разделение ответственности (Architect / Worker Separation)
- **Сабагенты** выполняют роль изолированных сборщиков и компрессоров данных. Они возвращают только факты, цифры и компактные выжимки.
- **Основной агент** держит общую стратегию задачи, принимает архитектурные решения и производит редактирование кода.

## 5. Политика работы с секретами
- Токены доступа (GitLab/GitHub API, сервисные ключи) запрашивать у пользователя строго через чат при необходимости.
- Запрещено сохранять токены в открытые файлы проекта, выводить в открытом виде в терминал или логировать.
